  OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Framework      : Next.js 14 (App Router) — already in place
Styling        : Tailwind CSS — already in place
Content source : Markdown/MDX files committed to GitHub (NO database for articles)
Deploy         : Coolify — auto-deploys on every GitHub push via webhook
Scraper        : OpenClaw MCP server feeds content into the GitHub repo
SEO            : Per-article metadata in frontmatter, auto sitemap, RSS feed

The key idea: articles are just .md files in /content/. Pushing to GitHub = 
publishing. Coolify rebuilds the static/SSR site automatically.

  THE PERSPECTIVE SWITCH (core UX feature)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When a conflict article is opened, both side-A and side-B content is loaded
server-side. The switch is a client component that toggles visibility.

Visual behavior:
  ┌────────────────────────────────────────────────────────┐
  │  🇺🇦 Ukrainian Perspective  ●────────  Russian Perspective 🇷🇺 │
  │  [colored banner changes color based on active side]   │
  └────────────────────────────────────────────────────────┘

- Switch state stored in localStorage so it persists across page reloads
- URL does NOT change on toggle (both perspectives share one canonical URL)
- Both sides are rendered in the HTML (one hidden via CSS) — good for SEO
- The active side's content is what Google indexes per canonical
- Structured data (JSON-LD NewsArticle) reflects the currently canonical side
- Social share button shares the current side's content

  OPENCLAW MCP SERVER INTEGRATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OpenClaw scrapes news sources for both sides of each conflict.
It then:
  1. Creates a properly formatted .md file (with full SEO frontmatter)
  2. Commits it to the correct path in /content/articles/[conflict]/[lang]/
  3. Pushes to the GitHub repo

On push → Coolify webhook fires → Next.js rebuild → article is live.

OpenClaw needs to know the conflict.json schema and the frontmatter schema
so it generates correctly structured files every time.

Suggested OpenClaw output contract:
  - File path   : content/articles/{conflict}/{lang}/{date}-{slug}-side-{a|b}.md
  - Frontmatter : all required fields (see Article Markdown Format above)
  - Body        : clean markdown, no HTML, no ads

  DEPLOYMENT FLOW (Coolify + GitHub)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Any push to main branch (articles, categories, or code changes)
2. Coolify receives GitHub webhook
3. Coolify pulls latest code + content
4. Docker build runs (next build)
5. New container replaces old one — zero downtime
6. New articles are live

No CMS, no database migrations, no deploy pipeline config needed per article.
Pushing a .md file IS publishing.
